# مشروع موقع A2B كامل

هذه نسخة مستقلة عن جهازك وعن استضافة ChatGPT. تشمل الواجهة العربية والإنجليزية، الحركة، معرض الأعمال، نتائج الحملات، حسابات المستخدمين، نماذج العملاء والتوظيف، لوحة الإدارة والصلاحيات، والصور وملف البورتفوليو PDF.

## متطلبات الاستضافة

استضافة تدعم **Node.js 24 أو أحدث**، تشغيل عملية Node باستمرار، HTTPS، وقرصًا دائمًا لقاعدة SQLite والصور المرفوعة. المشروع لا يحتاج حزم npm لتشغيله. استضافة HTML فقط أو PHP فقط لا تشغّل الحسابات والداشبورد. الاستضافة التي تحذف القرص عند إعادة التشغيل لا تصلح لحفظ الطلبات والحسابات.

## تشغيل وتجهيز حساب المالك

1. ارفع مجلد المشروع كاملًا، بما فيه frontend وbackend وdrizzle وscripts.
2. انسخ `.env.example` إلى `.env`. ضع رابط الاستضافة في `PUBLIC_URL` مثل `https://your-domain.example`، ومسار قرص التخزين الدائم في `A2B_DATA_DIR`. غيّر المثال لرابطك الفعلي.
3. من Terminal الاستضافة شغّل `npm run setup:owner` مرة واحدة. اكتب اسم المستخدم ورقم الهاتف وكلمة مرور جديدة؛ كلمة المرور لا تظهر أثناء الكتابة. البريد الأساسي هو a2begypt@gmail.com. إذا جهّزت الحساب قبل الرفع، ارفع مجلد data الناتج بشكل خاص خارج مسار ملفات الويب العامة وعلى القرص الدائم؛ لا تنشره في Git أو ضمن الواجهة.
4. أمر البناء: `npm run build`. أمر تشغيل الاستضافة: `npm start`. المنفذ يؤخذ تلقائيًا من `PORT` الذي توفره الاستضافة، أو 3000.
5. افتح رابطك ثم `/admin` وسجّل بحساب المالك. الزيارة بدون حساب فريق تظهر شاشة دخول فقط.

للتجربة على جهازك، اترك PUBLIC_URL فارغًا وشغّل `npm start` ثم افتح http://localhost:3000. التشغيل المحلي يتوقف عند إغلاق الجهاز؛ استمرار الموقع بعد إغلاق جهازك يأتي من تشغيل هذه النسخة على خادم الاستضافة.

## إدارة الفريق والمحتوى

- Owner: المحتوى والطلبات والحسابات وإعدادات SMS.
- Manager: المحتوى والطلبات.
- Editor: المحتوى فقط.
- Submissions: طلبات العملاء والتوظيف فقط.

ينشئ المالك حسابات الفريق مع المسمى الوظيفي والصلاحية. كلمة مرور الموظف الأولى مؤقتة ويجب عليه تغييرها قبل دخول الإدارة. إنشاء حساب عادي من الواجهة لا يعطي صلاحية إدارة.

من الداشبورد يمكن تعديل النصوص باللغتين، الكاركتر، الصور، الأقسام وترتيبها، أعمال الشركة، نتائج الحملات، أزرار التواصل، إعدادات النماذج وPDF. تعديلات الإدارة محفوظة في قاعدة البيانات؛ ملفات frontend هي محتوى البداية.

## البيانات ونسخ الاحتياط

تُنشأ قاعدة البيانات والجداول تلقائيًا عند أول تشغيل. لم تُرفق حسابات العملاء أو الموظفين أو كلمات مرورهم أو مفاتيح الخدمة من النسخة السابقة. الحسابات والطلبات السابقة لا تنتقل تلقائيًا بهذه الحزمة.

البيانات في `A2B_DATA_DIR`: ملف a2b.sqlite، ملفات SQLite المرافقة أثناء التشغيل، ومجلد uploads. خذ نسخة احتياطية للمجلد كاملًا بعد إيقاف عملية الموقع بشكل منظم. احتفظ بـ .env بشكل خاص أيضًا. شغّل نسخة واحدة من التطبيق على قرص دائم واحد؛ هذا الإصدار لا يتشارك قاعدة البيانات بين عدة سيرفرات.

## استرجاع كلمة المرور بالـSMS

تكامل Twilio Verify موجود، لكن إرسال OTP يحتاج حساب Twilio فعليًا ومفاتيح الخدمة. ضع TWILIO_ACCOUNT_SID وTWILIO_AUTH_TOKEN وTWILIO_VERIFY_SERVICE_SID في إعدادات الاستضافة السرية. أو ضع OTP_ENCRYPTION_KEY عشوائيًا من 64 خانة hex ثم اربط الخدمة من لوحة المالك. لا تشارك هذه المفاتيح مع العملاء ولا تضعها داخل Git. عند غياب الخدمة لا يدّعي الموقع إرسال كود.

## الملفات

- frontend: HTML/CSS/JS والصور والخطوط وPDF.
- backend: مصدر منطق الحسابات والنماذج والإدارة.
- server.mjs وstorage.mjs: خادم Node وSQLite وتخزين الصور.
- drizzle: ترقيات قاعدة البيانات.
- compiled: نسخة backend مبنية، يُعاد بناؤها أثناء التشغيل.
- scripts/create-owner.mjs: إعداد المالك من Terminal فقط.

ملف A2B-Company-Portfolio.pdf هو البورتفوليو النهائي داخل frontend. لا ترفع مجلد المشروع على أنه ملفات ثابتة فقط؛ شغّل server.mjs أو npm start كي تعمل الواجهة والباك إند معًا.
